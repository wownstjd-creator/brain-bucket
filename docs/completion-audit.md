# 구현 점검 및 남은 작업 — 2026-10-11

점검 기준은 2026-10-10 통합 소스와 자동 DB 업데이트 패치를 적용한 코드입니다. 친구의 H2 예비본을 기준으로 판단하지 않았습니다. 이후 GitHub 변경은 이 환경에서 확인하지 않았습니다. 최종 요구사항이 없으므로 코드상 결함·기능 누락과 별도 기획이 필요한 기능을 구분합니다.

## 이미 연결된 기능

회원가입·세션 로그인·로그아웃·CSRF, 작성/조회/수정, 포스터·증빙·원본 첨부, 승인/반려, 게시 시작/종료, 내림/복구, 일정 변경 이력, 승인 당시 본문·첨부 보존, 수정 후 재승인, 공개/아카이브, 스크랩, 세션별 조회수, 검색·분류·연도 필터, Flyway 자동 DB 생성/변경입니다. 사용자 로컬에서 핵심 UI 흐름과 스크랩·조회수·검색까지 동작 확인이 보고됐습니다.

## 이번에 바로 수정한 결함

| 발견한 문제 | 수정 | 근거 파일 |
| --- | --- | --- |
| 임시 저장도 제목·주최자·확인 체크를 강제 | 임시 저장에는 확인 체크/제목/주최자 필수 요구 제거. 승인 요청에는 유지 | PosterCapture.tsx |
| 글 수정 시 showViewCount:true 고정 | 기존 설정으로 초기화하고 조회수 표시 체크로 수정 가능 | PosterCapture.tsx, types.ts |
| 날짜만 입력하면 시간 필수 오류 | 날짜만 있는 행사는 00:00, 마감은 23:59. 날짜 없는 시간만 입력은 오류. 화면에 정책 안내 | formRules.ts, PosterCapture.tsx |
| 선택 URL이 빈 문자열로 저장 | 비어 있거나 공백만 있으면 null, 제공된 URL은 앞뒤 공백 제거 | api.ts, formRules.ts |
| 구체적인 오류 사유가 화면에 안 나오는 경우 | 상태/검증/JSON/업로드/수정충돌 오류에 일관된 message JSON 제공, 프론트에서 message와 ProblemDetail.detail 둘 다 처리 | ApiExceptionHandler.java, api.ts |
| 게시하기 비활성화 이유가 불분명 | 로그인·내용 확인 상태에 맞춘 설명 추가 | PosterCapture.tsx |

웹 입력은 원본 사진을 선택한 뒤 브라우저에서 JPEG로 변환합니다. 화면의 입력 한도 20MB와 서버의 전송 한도 10MB는 서로 다른 단계입니다. WebP 원본을 그대로 서버에 보내는 방식이 아니므로 이 차이를 단순 형식 오류로 판단하지 않았습니다.

## 실제로 없는 기능 / 다음 개발 순서

| 순서 | 코드에서 확인한 상태 | 제안 작업 |
| --- | --- | --- |
| 1 | 완료: 작성자 삭제 API·UI | 논리 삭제, 소유권/version 확인, 공개·현재 첨부·스크랩에서 제외. 처리 이력 보존 |
| 2 | 완료: 승인 대기 취소 API·UI | PENDING → DRAFT, 행 잠금/version 확인, 취소 이력 기록 |
| 3 | 완료: 첨부 제거 API·UI | DRAFT/REJECTED에서 소유자만 제거. 이력 참조 파일 유지, 비참조 파일은 커밋 후 정리 |
| 4 | 완료: 전체 페이지 수집과 상세 HTTP 반복 호출 제거 | 공개/스크랩 서버 조건·페이지 조회, 관리 상태 서버 필터, 내 글/관리 카드 API |
| 5 | 완료: 비밀번호 변경. 메일 재설정은 미구현 | 현재 비밀번호·새 값 검증, BCrypt 저장, 현재 기기 로그아웃 |

1~3은 이번 후속 패치에서 구현했습니다. 4번 목록 조회 개선과 비밀번호 변경도 후속 묶음 패치에서 완료했습니다. 삭제와 관리자 내림은 별개이며 삭제된 글은 관리자 복구로 되살릴 수 없습니다.

## 구현 완료와 별개로 필요한 작업

- 학교 로그인/메일 인증, 실제 게시 허가/직인 검증, 템플릿·누끼 등은 아직 구현되지 않았으며 외부 연동·최종 기획 범위를 정해야 합니다. 현재 증빙 첨부가 직인을 자동 검증하는 것은 아닙니다.
- 제출용 요구사항/API/DB 명세와 피그마 문서를 실제 동작과 맞춥니다.
- 배포 Compose/Caddy와 DB·첨부 백업/복구 스크립트를 준비했습니다. 실제 Docker 실행·HTTPS 외부 배포·백업 복구 운영은 서버 환경에서 검증해야 합니다.
- 휴대폰 실기기 촬영/OCR, 오류 UX는 실제 환경 확인이 필요합니다.

## 이번 검증

프론트 테스트 16개 및 TypeScript/Vite 빌드 통과. 새 테스트는 선택 날짜/시간·빈 URL·오류 사유 전달을 검증합니다. 백엔드 HTTP 검증에는 잘못된 회원가입 입력, 잘못된 신청 URL의 구체 오류, null URL 초안 생성 사례를 추가했습니다. 백엔드 Maven verify/JAR 빌드 통과, H2/HTTP 테스트 3개 통과. MySQL 전용 테스트 1개는 접속 환경변수가 없어 이번에는 건너뛰었습니다(자동 DB 패치 때 MySQL8에서 검증한 항목). MySQL 구조 변경은 이번 패치에 없습니다.

## 후속 기능 검증

작성자 삭제·승인 취소·첨부 제거의 소유권, version 충돌, 상태 제한, 삭제 후 현재 조회 차단, 이력 파일 보존을 통합 테스트로 검증했습니다. Maven verify는 4개 통과, MySQL 전용 1개는 환경변수 미설정으로 건너뛰었습니다. 프론트 테스트 16개 및 TypeScript/Vite 빌드 통과. 이번 후속 패치도 DB 컬럼 변경은 없습니다.
